# Quality and evidence

`tools/quality/definitions.ts` is the check-ID/requirement/command source. `pnpm check` runs project-local Vite+ formatting, lint and strict type checking once, plus runtime boundaries, dependencies and documentation, including standard skill YAML name/description and directory identity. Root options are common; package Vite configs own runtime/test/build only. SDK runtime types and generated route trees are excluded from formatting/lint, not silently substituted for source checks.

`pnpm test` runs tooling and package unit/contract tests. `pnpm gate:pre-pr -- --base <sha>` selects changed packages and reverse dependencies using real manifests. Root tooling/config/lock changes and an unknown base select everything. `pnpm gate:full` runs selected configuration checks, builds, real Worker tests, browser/a11y/VRT, [all-100 Lighthouse](lighthouse.md) and native tests. Static checking remains global because it is lightweight. Missing scripts, no tests, failures and timeout fail. A nonselected package is `not_required` with a graph reason; blocked checks never count as passed.

Checks run sequentially to bound native/runtime memory; Vitest limits workers, and Vite+/Cargo own their task/build caches. The gate does not reuse previous successful reports. pnpm/Rust dependency caches accelerate warm execution without approving a different input. Reports in `artifacts/gate-*.json` include Git SHA/base, source content ID, OS/Node, selection, commands, timings and results. The gate rejects unexpected source changes; perform typegen/codegen with setup first.

CI retains root reports, package reports and package `test-results` on failure as well as success. Evidence archives preserve those project-relative directories, including Playwright's actual/difference screenshots and trace; a JSON attachment path alone does not preserve the referenced file.

The Playwright browser uses grayscale text antialiasing with Chromium's `--disable-lcd-text`, so host LCD subpixel preferences do not alter screenshot glyph edges. Existing reviewed baselines and zero differing-pixel allowance remain in force. This setting belongs to the browser regression environment; production application rendering and official Lighthouse browser profiles are unchanged.

Git hook installation is repo-local and repeatable. Existing `core.hooksPath` or active user hooks cause an explicit conflict; migrate them intentionally. Pre-commit validates a temporary exact index tree, links dependencies without pointing workspace imports at unstaged source, and never formats/restages/stashes. Pre-push checks detached copies of the actual pushed commits against each ref's remote SHA; it runs static/unit checks. Heavy build/runtime/native verification runs in the PR and final gate. The tiny shell Git adapters are the only Git-required shell entry; their work is Node TypeScript. No Agent-specific hook is advertised.

`pnpm template:verify` validates all selected generated configurations; `--faults --hooks --lifecycle` adds isolated fault, real Git event, HMR and lifecycle rehearsals. CI selects these mechanisms when their shared foundations change. Standalone `pnpm template:faults` also copies the selected project into an owned temporary directory; it never injects faults into the user checkout. Each fault must fail for the expected reason and pass after repair. CI runs this independently even if hooks were not used. Visual baselines are reviewed screenshots of the new sample; do not update them solely to silence a failure. Native E2E uses actual app/Rust IPC on the target OS; renderer units have separate names.

Normal project checks use `pnpm exec vp`. `verifyDepsBeforeRun: false` keeps script/exec entrypoints from silently installing dependencies; explicit setup and frozen installs own preparation. Missing dependencies still fail the doctor and mandatory checks. The exact staged snapshot invokes that same installed local Vite+ CLI directly to keep index validation read-only with its linked dependencies.

Use `pnpm acceptance:report -- --evidence <collected-artifacts-directory> --sha <generation-source-sha>` to derive the preset/OS/check/requirement matrix from the same preset registry and check definitions. Generated gates record source provenance, exact content, tool versions, commands, durations and build sizes. Missing, stale, failed, skipped or blocked required execution evidence produces a blocked report and a nonzero exit. Windows Worker CI evidence is mandatory alongside the native OS matrix; it must match the current clean source SHA, content ID, configuration and complete workspace/check graph. A Linux, dirty, narrowed or renderer report cannot satisfy it. Canonical workspace, checks and generation receipts are validated before choosing a baseline from mixed archives. Real Agent rehearsal reports are separately collected evidence; running a script never substitutes for an Agent. The report covers execution evidence; it does not grant merge approval or replace required GitHub checks and reviews. Report GitHub Template settings, protection/rules access, security audit findings and remote deployment separately when assessing all Issue conditions.

`node tools/quality/sanitize.ts --rules <external-rules.json>` scans source, dependency manifests, configuration, documentation and built bundles against task-specific extraction rules. Supply entries with `id`, `pattern` and optional exact-file `allow` entries with a reason. Product identifiers belong in that review input, never in general downstream lint policy. Legal/source-provenance exceptions must be explicit. Scanner errors report file/rule identifiers without printing matching secret text.

Hook, fault, lifecycle and template rehearsal reports include final owned-directory cleanup. They publish success only after cleanup; a cleanup failure replaces the report status with `failed` and propagates the error. Completed inner phases do not turn an unsuccessful wrapper into accepted mechanism evidence.

[Security CI](security.md) additionally blocks HIGH/CRITICAL Trivy, ERROR Semgrep and incomplete scans. Its optional tools do not replace runtime gates. Never merge with an unresolved required security failure.

Type-aware lint rejects floating Promises even behind `void`, misused async callbacks and unhandled union cases; hooks, React keys, focused/disabled tests and explicit `any` also fail. [Failure contracts](errors.md) add Result/SDK ownership rules and catalog drift checks. The index hook runs structural lint; full quality runs types. Static JavaScript validation checks TypeScript/catalog documentation only; selected native checks additionally compare generated Rust and run Cargo formatting/Clippy. No Rust toolchain is needed for a Web/API project.

The required observability CI job runs a renamed/scoped generated fullstack project without the source checkout. It exercises real HTTP/browser CRUD, official read-only MCP and ClickHouse logs/traces/histograms; it validates failure and repaired trace IDs. When native work is planned, it requires current source SHA/content ID and save/cancel/error payload artifacts from each real Linux/macOS/Windows job, then verifies their actual Collector ingestion and correlation. Historical, renderer-only or fixture-generated payloads cannot satisfy this native condition.

The registry also owns `real-signals-mcp`: the optional Docker/MCP profile is verified once in CI using a separately named/scoped generated fullstack project without a source checkout. [Observability evidence](observability.md) requires actual ClickHouse logs, traces and histogram exemplars, readiness and bounded read-only MCP; if native is selected, all save/cancel/error producer artifacts from Linux/macOS/Windows must match the current source SHA/content ID and reach ClickHouse. `acceptance:report` requires this evidence alongside existing gates and rehearsals. Initialization failures replace old success with `not_run`/`failed`; source mutation and cleanup failures invalidate success.
