Reviewed again on 2026-10-11 UTC; earlier dated adoption measurements are historical. The manifests and locks are authoritative; this document explains their ownership. Applications and portable libraries live in `packages/*`. Canonical application blueprints live in `tools/generators/templates`; reference packages are regenerated with `pnpm template:sync`. Downstream generated projects own their application source.

Applications cannot import another application's implementation. Shared libraries cannot import Worker or native APIs. Startup dependencies are manifest relationships; they do not authorize cross-runtime source imports. Preset selection removes inactive manifests/catalog requirements before setup: Desktop-only excludes Cloudflare tooling, while web/API-only excludes Rust/Tauri. Root commands select the active graph; package scripts remain directly usable.

## Updates and retained versions

Official npm/crates registries, Node releases and GitHub release/tag records were checked for every catalog entry, every direct native crate, toolchain and pinned CI action. JavaScript releases must be at least 24 hours old. CI Actions remain pinned to verified commits. Update canonical blueprints, synchronize reference packages and regenerate locks; review Renovate proposals using that procedure, including proposals against derived Cargo files. Renovate configuration alone does not prove an installed App or a tested update.

The 2026-10-10 review updates Node 24.19.0 to the latest Node 24 LTS patch 24.21.0, Node 24 types 24.10.9 to 24.19.1, Rust 1.98.1 to stable 1.99.0, and CI mise 2026.9.12 to the newest release older than one day, 2026.10.4. Node 26.11.1 is the newer Current line, not the selected LTS line. `rust-version = "1.98"` declares the minimum supported compiler; `mise min_version = "2026.9.0"` declares configuration compatibility. Neither chooses the runtime used by checks. The unused direct catalog entry for tsx is removed; SDKs may still legitimately depend on it transitively.

At the review cutoff (2026-10-10 02:01 JST), cf beta.14 (~2h), config SDK 0.24.1 / Vite plugin 1.63.1 / Wrangler 4.149.0 / Miniflare alpha.1 (~23h), Tauri JS API 2.12.2 (~15h), Knip 6.41.0 (~9h) and mise 2026.10.5/6 (<24h) are held by the maturity rule. Miniflare alpha is required by the adopted programmatic configuration SDK; replacing it with the older stable Miniflare would change that SDK contract. WDIO 10 is available, but the latest Tauri service's official peer range is `webdriverio ^9.0.0`; the selected 9-series versions are the newest releases in their supported lines. Undici 7.29.1 is the Miniflare-owned dependency; its newer major 8 is not independently substituted.

`pack.external` is replaced with the installed Vite+ pack SDK's `deps.neverBundle`. The Vite+ owned lint/format/compiler components are updated through Vite+, rather than independently overriding its internal SDK. pnpm's esbuild/workerd build-script permissions remain narrow; unused Edge/Gecko driver download scripts remain denied.

The final self-review also updates direct `@wdio/types` from 9.31.2 to the mature supported 9.32.0 release; the CLI already uses 9.32.0 internally. Older Node declarations remain transitively locked through `@types/ws` / `@types/yauzl` and WDIO's Node 20 types. These declarations do not select an older Node runtime. Internal SDK types are not forcibly unified with the project's direct Node 24 declarations.

The official mise archive checksum, aqua-selected pnpm version, strict supply-chain checks for 983 entries, a frozen 758-package installation and project-local Vite+ CLI all passed in an owned minimal workspace. Only pnpm package-manager metadata changes in the lock; the application dependency document remains byte-identical. See the dated adoption record for measurements and limitations.

Dependency preparation belongs to explicit setup/install. pnpm's documented `verifyDepsBeforeRun: false` disables its implicit pre-script/pre-exec install, keeping `env:doctor` and generator `--no-install` from preparing application dependencies. The shipped lock still pins package-manager metadata; deleting it requires restoring or explicitly preparing that metadata. Missing application dependencies remain errors in doctor/checks, and frozen-lock, release-age and supply-chain verification remain mandatory.
