# Failure contracts and generated errors

`tools/errors/catalog.json` is the only authored error vocabulary. It defines internal-to-public projection, HTTP status, finite failure class, retry ownership, fixed public message and remediation. `pnpm errors:generate` derives TypeScript in contracts, Rust in each selected Desktop and [the catalog report](errors.generated.md). `pnpm errors:check` detects drift without writing. Application generation reads the current catalog directly; it has no second error blueprint. Cold Desktop setup finalizes Rust formatting only while the file matches its ownership hash. Explicit regeneration replaces generated outputs; edit the catalog, review the diff and commit them together.

Expected domain/SDK failures use `Result<T, AppError>` internally. Portable UI ports use `Result<T, PublicError>`. Always inspect `ok` and propagate, retry at the named owner or present the fixed error. Async Result ports must state their return type; contextual UI adapters use the shared interface. `capture`/`captureSync` take thunks so both synchronous throws and rejected promises normalize at SDK ingress. `capturePublic` validates serialized native errors. Untrusted success payloads pass through shared schemas; public error decoding validates the whole fixed policy, not merely the code. Raw causes/messages are not transported or logged.

HTTP and Tauri commands are projection boundaries: record the internal failure once, return the generated public policy with a 32-character diagnostic ID, and preserve trace context. A transport/UI callback may require `Response`/void; its exact live file:function boundary and reason belong in the owning manifest. A boundary does not permit throw/catch, discarded Result or private telemetry. UI event `launch` owns unexpected synchronous throws/rejections; applications do not use `void promise`, `catch(() => [])` or Error-instance checks for JSON IPC rejection. Validation/forbidden/not-found/cancellation are expected outcomes; unexpected infrastructure defects become opaque internal failures. Cancellation has INFO/unset telemetry and no automatic retry.

The retry field says who may decide; it does not initiate retries. Validation failures never retry. Transient/unknown outcomes require the owner to reassess idempotency and state before retrying; the template has no hidden retry loop. Export failures preserve business results and report finite exporter health separately. SDK/programmer configuration invariants may throw only in the contracts/observability owners; this is not permission to throw expected failures in applications.

`pnpm check` combines project-local Vite+ type-aware lint, import/runtime checks, Oxc AST failure rules and generated drift. The index hook applies structural rules without worktree typegen. It detects discarded known Result helpers and declared local Result functions; it is not a general effect system for arbitrary external TypeScript. Typed ports, no-floating-promises with `ignoreVoid:false`, no-misused-promises, exhaustive switches, no-explicit-any, native unused_must_use and Clippy form the complementary gates. Tests and transport-owned callbacks remain subject to their actual runtime assertions. Exceptions are exact, reasoned and stale-checked; the observability role is reserved for the shared library.
