# Cloudflare local development and deployment

Each Worker owns one `cloudflare.config.ts`; Vite+ and the Cloudflare Vite plugin generate runtime types and Build Output. Do not hand-maintain Wrangler config alongside it. `local`, `dev` and `production` are explicit SDK environments; unknown names fail. Vite reserves the name `local`, so scripts pass Vite mode `offline`, mapped explicitly to SDK `local`. The cf type/migration commands use SDK mode `local` directly.

Selected D1/KV/R2 produce only those bindings. D1's deterministic local UUID, migrations, seed and dev runtime use the same `.state/<directory>`; setup migrations are repeatable, and initial seed is not replayed after deletion. Cloud-free tests use actual workerd; no accounts/tokens are needed. Volatile configurations say that their data resets. Fullstack Web depends on the API's manifest package for ordering, and communicates by Service Binding rather than code import. Both local root startup and CI start the API before Web. Desktop's adapter stays offline.

Remote artifacts deny unauthenticated writes and have no default workers.dev/preview publication. Configure existing approved dev resources: `CLOUDFLARE_ACCOUNT_ID`, selected `D1_DATABASE_ID`, `KV_NAMESPACE_ID`, `R2_BUCKET_NAME`, plus a narrowly scoped `CLOUDFLARE_API_TOKEN` only for an authorized deployment. Use your existing secret store or an ignored local environment file; never embed tokens into Web/Desktop or print their values. Supply environment variables explicitly to the command. Unknown/missing IDs fail; no resource provisioning/fallback is performed. Add an explicitly approved dev route/domain in the sole config before remote smoke.

Run `pnpm deploy:preflight -- --target api --environment local` for credential-free local validation; it runs quality, tests, actual runtime and build, then records the input/artifact. Use environment `dev` for connection preflight. Missing account/resources fail with configuration guidance, and are not a deployment success. `pnpm deploy -- --target api --environment dev` requires the user's authorized dev environment and credentials, deploys only the newly checked prebuilt artifact with auto-provisioning disabled, and never runs from setup/build or ordinary CI. Deploy API first, smoke the explicitly configured dev route, then Web. For a bound Web deployment, use the same checked prebuilt `cf deploy --prebuilt --no-provision -m dev` package entry after confirming its upstream deployment. No undeclared environment or production fallback is allowed. Clean up only temporary resources created for that authorized rehearsal; never replace/delete existing resources.

If choosing Workers Builds instead of manual dev delivery, set repository root as root directory, build command to `mise install && pnpm install --frozen-lockfile && pnpm env:setup && pnpm gate:pre-pr -- --base <base-sha>`, then build the explicit Worker in mode `dev`. Set its deploy command to the prebuilt cf command for that package, supply the same named-account/resource settings and narrow token, and configure API-before-Web order. Watch the owning package, its shared dependencies, tools, root configs, catalog and lockfile. Do not configure a second Actions deployment. This repository's ordinary Actions workflows perform checks only.

Actual Cloudflare deployment, remote Binding connectivity, domain routing, credentials and Renovate/GitHub App connection require external setup and are not claimed by a local build. Production delivery and signed public Desktop releases are separate work.
